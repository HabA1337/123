# Починка Cursor, который не запускается

Скрипт `fix-cursor.bat` для Windows. Он лечит случай, когда Cursor не открывается даже после переустановки.

## Почему переустановка не помогает

Установщик меняет только `Cursor.exe`. Профиль `%APPDATA%\Cursor` остаётся, а в нём хранится список окон, которые Cursor открывает при старте. Если приложение зависло на папке с проектом, новый `Cursor.exe` при запуске снова упирается в то же состояние.

Второй частый случай — сломанное автообновление: старый `Cursor.exe` удалён, новый не дописан. Тогда ярлык ведёт в пустоту.

## Как запустить

1. Скачайте `fix-cursor.bat` кнопкой **Download raw file** на GitHub, или прямой ссылкой:
   `https://raw.githubusercontent.com/HabA1337/123/cursor/cursor-repair-script-b6d3/tools/cursor-repair/fix-cursor.bat`
2. Положите файл на рабочий стол.
3. Нажмите на нём правой кнопкой → **Запуск от имени администратора**. Без админа пункты 4 и 5 работать не будут.
4. Введите **9** и нажмите Enter. Это рекомендуемый режим: диагностика, чистка кэша, сброс профиля с бэкапом, запуск.

Меню на английском, чтобы в cmd не было кракозябр вместо русских букв.

## Что делает каждый пункт

| Пункт | Действие | Опасность |
|---|---|---|
| 1 | Собирает отчёт: есть ли `Cursor.exe`, висит ли процесс, хвост `main.log`, исключения и карантин антивируса | ничего не меняет |
| 2 | Снимает процессы Cursor, удаляет `Cache`, `GPUCache`, `Code Cache`, `CachedData` | безопасно |
| 3 | Переносит `%APPDATA%\Cursor` в `Cursor.bak-<дата>`, создаёт чистый профиль и копирует туда `settings.json`, `keybindings.json`, `snippets` | обратимо пунктом 7 |
| 4 | Удаляет `%LOCALAPPDATA%\Programs\cursor` и остатки обновления, открывает страницу загрузки | удаляет только программу, не настройки |
| 5 | Добавляет папки Cursor в исключения Windows Defender | нужен админ |
| 6 | Запускает Cursor с `--disable-extensions --disable-gpu -n` | безопасно |
| 7 | Возвращает профиль из бэкапа, вместе с историей чатов | отмена пункта 3 |
| 8 | Лечит `settings.json`: значения, которые должны быть списком, но записаны строкой. Из-за них Cursor закрывается сразу после запуска | делает копию файла |
| 9 | 1 → 2 → 8 → 3 → 6 подряд, с одним подтверждением | обратимо пунктом 7 |

## Что скрипт не удаляет никогда

- `%APPDATA%\Cursor\User\globalStorage\state.vscdb` — там локальная история чатов. При сбросе она уезжает в папку бэкапа целиком.
- `%USERPROFILE%\.cursor` — настройки CLI и MCP, к запуску приложения отношения не имеют.
- Ваши проекты и файлы кода.

## Cursor открывается и сразу закрывается

Это отдельная поломка, переустановка от неё не спасает. В `%APPDATA%\Cursor\logs\<дата>\main.log` видно строку:

```
TypeError: (this.configurationService.getValue(...) || []).map is not a function
    at Wf.onConfigurationUpdated
```

Значит в `settings.json` лежит настройка, которая по схеме должна быть списком, а записана строкой. Чаще всего это `http.noProxy` после настройки прокси или VPN:

```json
"http.noProxy": "localhost,127.0.0.1,::1"
```

Правильный вид:

```json
"http.noProxy": ["localhost", "127.0.0.1", "::1"]
```

Пункт 8 делает эту замену сам и оставляет копию исходного файла рядом. Это известная ошибка Cursor и VS Code: невалидное значение должно игнорироваться, а вместо этого падает главный процесс.

## Отчёт

Пункты 1 и 9 сохраняют файл `cursor-diagnostics.txt` на рабочий стол. Его можно прислать в чат: по нему видно, удалил ли антивирус `Cursor.exe`, зависает ли процесс и на чём падает запуск.

## Если приложение открылось

Не открывайте сразу папку, на которой всё зависло. Сначала пустое окно или маленький проект. Затем выключите автообновление: `Ctrl+,` → `update.mode` → `none`, иначе установка может сломаться снова при выключении компьютера.

## macOS и Linux

Скрипт только для Windows. Пути к профилю:

- macOS: `~/Library/Application Support/Cursor`
- Linux: `~/.config/Cursor`

Логика та же: переименовать профиль, запустить, при успехе вернуть `settings.json`.
